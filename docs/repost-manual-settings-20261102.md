# 手动搬屎回执与 B 站插件设置整合

## 修复

生产日志中的微信媒体调用在默认 30 秒 RPC 等待后抛出 `RPCError`，手动入口随后把未知回执报告成失败。媒体发送现在使用 180 秒 RPC 等待；手动原生命令 / API 使用 600 秒，壳子等待 660 秒。超时不代表平台未发送：未知、排队中或超时回执保留为未确认，不自动重发，不广播失败，也不记为确认送达。明确的选片、下载或发送失败仍可提示一次。

设置位置统一为 **插件管理 → B站搬史机 → 配置**。旧版检索、艾特率、定时等视觉表单全部隐藏；原配置值和原始配置兼容入口保留。Story 开关、账号推荐、UID、入口 aid、`/bv` 标签联动使用原生表单；同页嵌入标签增删改、权重、四种导入模式和扫码 / 验证 / 清除授权。表单由插件保存按钮提交，嵌入页动作明确提示即时保存。

自定义页继续使用现有注册声明、沙箱、主题与 API 权限网关。配置 schema 的 `embedded_webui_page` 与注册表响应的 `config_page_id` 只决定嵌入位置和独立导航隐藏；不扩展严格页面声明协议，不使旧 Host 的插件热重载失败。

- `scripts/repost_dual_delivery_acceptance.py`：16/16，覆盖双端路由、发送回执、去重、调度与独立目标。
- 前端注册表、嵌入页、沙箱页测试：22/22；TypeScript 检查与生产构建通过。附加 Header 测试 16 通过、6 失败；用 HEAD 原版相关模块复测得到相同六项失败，属于既有问题。
- 真实浏览器加载构建后的主站插件配置页，查询实际标签，验证搜索和嵌入沙箱、旧表单隐藏与独立导航移除。运行中的 Host 尚未加载新增序列化逻辑，浏览器仅对只读注册表响应补入已通过后端测试的 `config_page_id`，模拟用户下次重启后的展示；未改真实配置、授权或向群发送消息。
