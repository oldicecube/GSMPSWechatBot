# /bv 与自动解析支持 b23.tv 短链

已完成，未重启 bot，未向真实微信群发送测试消息，没有新增配置项。

## 使用方式

在启用自动化插件的目标群中，消息任意位置包含 `https://b23.tv/短码`、`http://b23.tv/短码` 或 `b23.tv/短码`，即可进入现有 `/bv` 下载解析队列，无需 @ 或命令前缀。`/bv https://b23.tv/短码` 和整段 B 站分享文案也受支持。原有 BV 号与视频长链接继续可用。

沿用现有群开关、WebUI 管理状态/权限/冷却、共享 FIFO 队列、任务数量、文件大小及时长限制，不改变配置。每条消息处理一个视频，多个短链时取第一个；非视频短链、失效链接或上游失败会反馈错误。

## 实现

- `auto/bv.py`：在原 BV 本地检测之外识别 b23 链接，转交原命令插件；消息线程不执行网络展开。
- `plugins/bv.py`：短链可直接入队，后台继续执行原有解析、下载、发送与清理；短链生成安全的本地文件名，避免把 URL 中的 `/`、`?` 等写入 Windows 文件名；沿用原插件上下文和消息来源记录。
- `services/bilibili.py`：统一提取嵌入文字、中文标点、无协议链接及 HTML 转义参数中的短链。按 HTTP `Location` 展开，最多请求 5 跳，逐跳检查 b23/B站域名并限制等待时间；不下载最终视频页 HTML。最终只取 `/video/BV...` 或 `/video/av...` 路径中的标识，保留目标分 P，防止将跟踪参数中的 BV/AV 当成实际视频。循环跳转、404/429、无跳转、非视频及越界地址均明确报错。

调研参考：[bilibili-api-collect 的 b23.tv 格式和短链接口记录](https://github.com/bilibili-plugins/bilibili-api-collect/blob/master/docs/misc/b23tv.md)。复用仓库已有 requests 与视频下载服务，没有安装额外解析库或调用第三方解析 API。
