# 插件清理、积分规则与帮助图片

## 完成内容

- 删除 `plugins/guide.py`、`home.py`、`lottery.py`（含 `/彩票`）、`notice.py`、`prompt.py`、`redeem.py`。它们不会再注册命令或出现在 WebUI 管理目录。历史积分与彩票等业务数据保留；未做历史奖励回收或投注自动退款。
- `/player fortune` 保留每日一次运势，移除全部加分代码和奖励提示；`/sign` 删除运势获积分提示，`/points help` 同步移除并纠正现有 Anima / echo 消耗文案。
- `plugins/help.txt` 重写为分组命令手册，去掉退休及目前停用的 FX / persona 等功能，补齐双端转发、b23、随机轴对称、绑定和真实积分规则。帮助插件每次读取文本，不缓存正文。
- `/help` 复用 `/acgpic` 的 API / 有界下载功能取随机竖图，按画布比例裁切、降亮度、模糊；根据亮度选择深浅卡片、文字与强调色。两列卡片随正文自动测量高度 / 换行，避免孤立标点。只发送一张 JPEG，不再附带重复的长文本。
- 展示前按实际插件目录、WebUI 启停、平台限制、群功能与命令权限过滤；例如微信不显示 `/wx`、QQ 不显示 `/qq`。`/shit tb` 只检查手动贴吧来源，暂停自动搬屎不等于删除其显式手动入口。后台图片源不可用时用简洁背景，帮助功能仍能出图。临时背景与输出均在发送完成后清理。
- 原 `/ban` 存在 SQLite 写入 / JSON 读取分裂，以及仅接受 wxid / 旧微信管理员的缺陷。现在壳子 Router、微信监听前和 MaiBot 原生接收前共用一个 SQLite 黑名单，兼容原 JSON 迁移；微信以 wxid、QQ 以 `qq:QQ号` 区分，不靠昵称或绑定继承权限。缓存随 DB / WAL 修改失效。
- `/ban <wxid或QQ号>` 可在两端使用，跨端目标可显式写 `qq:123456`、`wechat:wxid_xxx`；需要原管理员或原生命令授权。它禁止目标使用 bot，**不是 QQ 群禁言**。当前部署只有微信旧管理员，未给 QQ 账号擅自授予管理权限；可在 WebUI 的命令管理为 `gsmps.command.ban.invoke` 明确授权 `qq:QQ号`。
- 本地已备份并删除不再使用的 `lottery` / `print_server` 配置段。管理状态保留退休 ID 的 `enabled=false` 停用标记，防止运行进程里已加载的旧模块继续执行（特别是彩票定时线程）；文件已删，因此这些标记不会重新产生界面条目。新代码也拒绝执行已不在目录中的管理 ID。

## 生效与边界

未手动重启 bot。当前运行实例会立即读取退休 ID 的停用标记，但它已加载的 Python 类 / 函数不会因源码修改自动替换；新的帮助图、fortune 和 ban 核心修复需用户手动重启后完整生效。后续修改 `plugins/help.txt` 则立即在下一次 `/help` 中体现，不需要重启。

真实配置、备份、运行日志、背景图片和生成的预览只留本机，不提交至远端。
