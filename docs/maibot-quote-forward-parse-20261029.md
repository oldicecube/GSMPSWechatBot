# 微信引用与聊天记录解析验收

2026-10-29：已修复引用原文未进入模型、引用快照数据库恢复丢失，以及嵌套聊天记录解析不完整的问题。没有重启生产 bot；主进程 PID 14880，启动时间仍为 21:52:20。新增 Python 逻辑需要用户手动重启后生效。

## 发现的问题

1. 入站引用已构造 `ReplyComponent`，但原生上下文构造会去掉这个组件，仅在消息前缀标注引用 ID。被引用消息不在当前历史窗口时，Planner/Replyer 无法知道原文。
2. 原生数据库组件序列化只保留引用 ID，不保留引用正文和作者。仅修复即时上下文仍会在历史恢复后丢失窗口外引用。
3. 转发解析只读取每个节点的 `datadesc/datatitle`；`.//dataitem` 还会把嵌套记录错误展平。CDATA、多层实体编码、直接 XML 子元素等形式未统一处理。
4. `.//refermsg` 会匹配转发内部的引用，可能错误地让外层整条聊天记录获得一个回复目标。
5. `rawContent` 若只是显示标签，以前会阻止按精确消息标识补取原始消息。

## 实际修改

`llm/core/wechat_translation.py`：

- 仅读取当前外层 `appmsg/refermsg`，支持 `msg/appmsg` 和直接 `appmsg` 根元素；保留原始长 ID，纯本地引用 ID 使用与入站消息一致的会话命名。
- 引用链接、应用消息和聊天记录转为可读内容；引用图片等缺原始数据时提供明确说明，不把加密 XML 或密钥字段当作正文交给模型。
- 在原生允许的 `additional_config.wechat.quoted_snapshot` 中保存引用 ID、作者、正文和类型，兼容现有数据库结构和原生消息组件格式。
- 递归解析记录的直接节点，保留嵌套 `ForwardNodeComponent`；保留作者、实际用户 ID、节点 ID、原消息时间、文字、标题和链接。群聊 ID 不冒充节点作者。
- 兼容 recorditem/recordxml 的直接子元素、CDATA、实体编码；最多解码四层，转发最多八层、共 1000 节点。超过上限或内容缺失会明确标注。
- 只拿到显示标签时，按会话、localId/serverId 补取原始消息；保留原有 ID 一致性校验。

`src/maisaka/context/planner_messages.py`：

- 微信引用原文作为独立 `<quoted_message>` 块进入原生上下文，带作者、用户 ID、引用 ID 和 available 标志，与当前发言正文分开。
- 数据库恢复后从匹配引用 ID 的适配器快照读取内容；不改变原生数据库组件格式，也不伪造原文。
- 引用正文及属性执行转义，避免正文里的 XML 被误认为外层消息元信息；单引用模型快照最多 16000 字符，截断明确标注。
- 没有修改 MaiBot 原生人设、风格预设或出站发送逻辑。

`scripts/maibot_bridge_acceptance.py`：

- 新增八个针对引用和聊天记录的单测，并在真实原生链路中核对 Planner、Replyer 实际发送到本地模型夹具的请求。
- 增加数据库恢复、超过预览长度的完整浏览、嵌套路径浏览与无效路径拒绝验收。
- 测试夹具等待逻辑等待已调度/运行中的轮次；不会要求每条仅观察的消息都必须得到回复。

## 验收结果

最终桥接验收 **66/66 项通过**，其中转译、发送相关单测 **61 个通过**，失败和错误均为 0。三个改动 Python 文件编译通过。[机器可读报告](maibot-wechat-acceptance/quote-forward-20261029.json)

关键实测：

- 原消息完全不在历史中的引用：原作者、原文及当前正文同时到达 Planner 与 Replyer。
- 引用中的换行、特殊符号、链接、超长原始 ID、本地 ID 保留或准确转换。
- 引用快照入库后重新读取，仍可构造包含原文的上下文。
- 聊天记录在预览后还有内容，`view_forward_message` 能读取尾部；`path=[0,0]` 能展开嵌套记录；错误路径返回失败。
- 嵌套记录经数据库保存、重新读取后仍保持层级。
- 嵌套转发中的引用不再被识别为整条外层消息的回复目标。
- 引用合并聊天记录时，已有嵌套文字展开为引用快照，不提供无法访问的工具路径。
- 原有出站引用丢弃、真实 @、富媒体发送顺序及失败回执的回归测试继续通过。

测试仅使用本地合成消息和模型夹具，真实微信发送被拦截，没有向群聊发送验收消息，也没有将群聊原文发往外部 API。

## 解析边界

入站引用保留并提供给模型；出站微信引用组件继续按既有要求丢弃，仅发送正常正文和真实 @。

记录中的图片、语音、视频等，如果只有描述或加密附件元数据，当前会保留描述并明确标注原始内容不可用，不宣称已识别附件。历史数据若只存 ID、既无引用快照又无法找到原消息，不会编造正文。受限截断和无法展开的内容均有可见提示。
