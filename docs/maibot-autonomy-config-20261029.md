## 生效边界

后续按最新要求改为 `target.mode="planner"`：不再按每天 6 个固定计划直接搬运，原持久化日期计划保留但在 planner 模式下不执行。`daily_times=6` 仅作为以后明确切回 `scheduled` 模式的参数。统计来自原生历史接口，外壳解析过而只观察入库的 B 站消息同样可见，不依赖普通入站 Hook。自己的输出、已标记的外部 bot、跨群消息、重复 message_id、过期消息与引用中的旧链接均不作为新分享证据。

普通搬屎工具冷却仍为 600 秒；只有缓存的近期观察仍满足活跃门槛且达到密集阈值，工具冷却才缩短至 180 秒。二创频道保持 600 秒。提交给核心的决策时间与最新分享时间持久化，重载不会拿旧分享反复唤醒；RPC 超时也保留预留记录，因为请求可能已经排入核心。原生 planner 可以选择工具、聊天或保持安静，实际成功搬运还依赖聊天 LLM、候选质量与下载结果。本轮没有重启或停止 Bot，完整加载仍由用户手动重启。

首次启用验收时主进程为 PID 15256，启动于 10:26:08，当轮没有手动重启或停止；该进程信息为历史记录。配置与代码变更已保存，完整加载以用户手动重启后的运行实例为准。

旧 Runner 的人格插件实例仍驻留内存，其脚本定时器可能重新创建一个空 `maips/` 目录；这不包含清单或插件源码，重启后不会被发现或加载。本次不以删除磁盘源码冒充运行中实例已经退出。

生活日程生成和主动聊天仍依赖核心聊天 LLM。已有的聊天 API 429/超时不会因这些配置自动解除，计划存在或 Host 接受意图也不等于消息已送达。自动搬运还取决于实时搜索候选、评论门槛与下载是否成功；隔离验收未向真实微信群投递视频。
