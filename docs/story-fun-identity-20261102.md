# 2026-11-02：Story 搬屎、持久化乐子、身份与响应时段

## 当前行为

1. QQ / 微信人物用 `platform + user_id` 定位。昵称和群名片只做完整、区分大小写的精确匹配；同名歧义不选第一人，不再通过 JSON 字段的 `contains` 做人物识别。画像中明确保存的别称可以精确查找，待确认的建议别称不参与身份合并。已确认的双端绑定关系继续使用原身份关联服务。
2. 改昵称只更新当前昵称 / 群名片，不改人物 ID、记忆或明确保存的历史称呼。修复了群名片不变时昵称未落库的问题；当前画像缓存也不能覆盖最新身份字段。Planner、Replyer 的目标信息带平台与稳定用户 ID。
3. 外部机器人发言始终属于外部数据，不因插件来源标记而成为本机的 assistant 历史；主动任务使用本机机器人身份，不再借用最后一个群友的身份。超过 1 小时的消息可以作为历史背景，但不能作为新回复目标；旧 wait 锚点不会无限续接。
4. `autonomous_life` 默认使用 `fun.enabled=true`。旧 `mai-life` 自动日程生成与注入已在本机关闭，保留其明确提醒 / 查询功能；热点插件的独立定时唤醒也关闭，热点查询工具仍可用。
5. 乐子方向有标题、目标、类型、状态、真实检查点。Planner 使用 `fun_direction` 决定热点 `hot`、Story 视频 `video`、代码 `code`，可继续、搁置、放弃、查看或消费报告。每个群同时最多一个乐子任务，每日全局最多 12 次；沿用原生子代理并发上限，每轮最多 5 个工具轮次，总运行时限 600 秒。
6. 子代理只获得联网、热点、Story 元信息和隔离 Python 工具，不授予群发言、RCON 或管理操作。完成后先保存简报，再交回下一次 Planner；报告保留到明确消费。Planner 决定是否、何时、怎样自然分享，不由插件直接广播。原生乐子主动发言沿用原自主生活的全局每日最多 4 次与跨群间隔，在发送前持久化预约；失败或未知回执也占额。普通群聊中的相关接话不算新的主动广播。代码必须实际经过已有的隔离沙箱，实际代码、stdout / 文件成果也持久化，继续方向可读取上次实际代码。最多保存 1000 条有界工具步骤。旧项目按待核验方向保留，不把旧计划当作完成事实。

## 不响应时间段

沿用壳子 `config.json` 的 `time_slots`，按 `Asia/Shanghai` 判断。当前配置为 08:00 至次日 03:00，保持原来按分钟、端点包含的语义。

- 时段外暂停 LLM 聊天响应和自动搬屎；自动任务在投递前再次检查，避免长下载跨入静默时间后仍发送。
- Router 不再在命令识别之前丢弃全部消息。手动 `/shit bv`、`/shit tb`、原手动搬屎入口、其他指令、拍一拍、sleep 等自动插件仍走正常链路，群权限和插件开关照常检查。
- LLM 主动任务不能绕过时段限制；生成过程中跨入时段外的回复也不会发送。插件直接发送的正常结果不受此限制。
- 手动搬屎独立于自动搬屎开关，手动失败不会自动重试或声称已送达。

## B 站 Story

使用 `GET https://app.bilibili.com/x/v2/feed/index/story`，不以首页推荐、搜索结果或简单竖屏尺寸筛选替代 Story。

流程：

- 跨页聚合，每批 10 个不同视频；实际接口有时一页只有 5 条。
- 只选 `0 < duration <= 120` 秒的视频；按视频详情标签与配置标签精确匹配、每个标签计一次。
- 首先要求至少 3 个标签；20 条仍未匹配到后降到 2 个，50 条后降到 1 个，会重新考察已获取的候选。
- 同批分数为 **匹配标签权重之和 + 匹配标签数 × 2**，同分保留先来的视频。
- 预留前去重、确认发送后记送达；未知回执不重发。最多扫描 60 条不同视频 / 24 页，有界请求并发为 3。原有标题、标签、UP 屏蔽项继续有效。
- `story.enabled=false` 可退回旧搜索筛选；默认已启用 Story。

用户提供的标签报告已解析为 **333 个预置标签**，首次装载写入共享 SQLite，后续重载不重复覆盖或累加预置权重。

### 设置位置

MaiBot WebUI → 插件管理 → B 站搬史机：

- 原生「配置 → Story 竖刷推荐」：启用 Story、是否使用授权账号、期望 UID、入口 aid、`/bv` 标签联动开关。
- 插件工作区「Story 标签与授权」：标签查看、搜索、分页、添加、编辑权重、删除、TXT 报告导入、账号扫码 / 验证 / 清除。

页面使用现有插件 WebUI 协议、原生主题样式桥接和 API 绑定；不修改主站组件规范。TXT 在沙箱页读取后以有界文本提交，不使用仅支持图片的原生上传接口冒充 TXT 上传。选择文件后必须选择导入模式，并再次确认：

| 方式 | 同名标签 | 原配置独有标签 | 文件独有标签 |
| --- | --- | --- | --- |
| 完全覆盖 replace | 使用文件权重 | 删除 | 添加 |
| 部分覆盖 update | 使用文件权重 | 保留 | 添加 |
| 新增 add | 保持原权重 | 保留 | 添加 |
| 合并 merge | 权重累加 | 保留 | 添加 |

### 指定账号授权

UID 不能代替登录授权。先在页面申请二维码，用手机哔哩哔哩扫码确认，再核对返回 UID，并打开「使用已授权账号的推荐」。可填 `expected_uid` 防止授权到错误账号。

协议调研参考用户提供的 BewlyCat（审阅提交 `f11de77051bbc8896f9038e51cc3af88e737cc5c`）的 `appAuthTokens`、`authProvider`、`appClient`、`appSign`，及 bilibili-API-collect 的 Story 文档；实际实现按当前 Python / MaiBot SDK 编写。使用匹配的 HD AppKey 签名，`/x/v2/account/myinfo` 验证账号，支持到期刷新和清除授权；不同 AppKey 的 Token 拒绝混用。

Token 只保存在插件本机数据，不通过状态 API 返回明文，导入框为密码输入且提交后清空。撤销授权与刷新 / 导入并发时，旧请求不能恢复已撤销授权。二维码申请成功不等于账号已经登录。

### `/bv` 联动与 `/shit`

启用 `story.parse_linked_enabled` 后，`/bv` 命令、直接 BV / 视频链接、b23 短链及原自动解析入口最终共用成功投递回调；所有适配器、所有允许解析的群均可增加标签。每次成功请求，每个不同标签权重加 1；用平台、目标和原消息标识去重，失败发送不计入。

下载队列也按平台与目标群去重，同一视频在另一个微信群或 QQ 群的新请求不会被当成当前群的重复提交。

GSMPS 壳子新增 `/shit [bv|tb]`，省略参数时为 `bv`。它绕过 Planner，仅触发当前真实群的一次搬运，并等待真实回执。目标携带原平台、账号和连接；保留群和插件权限。

贴吧自动来源、独立定时和 LLM 贴吧工具已暂时关闭，保留显式手动 `/shit tb`。

## 模型超时与轮转

日志中出现同一个限速端点每 32 秒才能请求一次，而任务硬超时为 45 秒的组合。此前本地排队被算入模型生成时限，后台学习 / 图片任务容易在实际请求前后耗尽 45 秒。

- 模型真实网络请求独立计时，本地限速排队不再制造模型硬超时。
- 优先选择已就绪的模型 / 端点；限速中的高优先级端点先跳过，冷却结束后自动恢复原优先级，不永久降级。
- 同一端点 + 凭据共享本地限速槽和普通 429 冷却，换同端点的模型名不能绕过限流。检查与预约原子完成，处理并发争抢。
- 所有候选都受限时返回最短冷却时间，由原生恢复机制等待，不忙轮询；明确指定单模型 / 嵌入向量空间维持其专用语义，不随机切换向量模型。
