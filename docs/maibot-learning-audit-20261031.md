# 表达方式与黑话学习审计（2026-10-31）

## 实际问题

生产数据库并非“完全没学到”，而是同时存在三种问题：

1. `expressions` 有 545 条，其中许多旧迁移条目的 `style` 是 `legacy`，高频条目会占据候选池，但模型实际拿不到可复用的表达文本。
2. `jargons` 有 214 条；171 条只有一次出现，43 条出现过多次，但很多 AI 条目的 `meaning` 为空、`is_jargon=0`。`何意味`、`没绷住`、`卡丘`、`疯狂星期四`、`绷`、`艹`、`傻逼`等已经有 2–5 次证据，过去仍可能停在未完成状态。
3. 黑话含义推断在一次 `no_info` 后把 `last_inference_count` 推到当前次数，下一次要等很远的阈值；含义一直为空时也可能被标记为完成，导致后续不再复核。

## 已修改

- 黑话推断阈值调整为 `2 / 4 / 12 / 40`，并且空含义条目在新增两次证据后会再次尝试推断。
- 只有含义非空时才允许把条目标记为完成；含义为空不会永久封存。
- `learn_jargon`、`learn_style`、黑话比较和表达评估提示明确：优先高频、非标准、语境依赖的表达；粗口、脏话、阴阳和夸张语气可以学习；只跳过字面明确的普通口语。
- 表达候选池会从旧 `legacy` 情景中恢复紧凑、非 @、非拍一拍模板的真实短表达，例如“没绷住”“何意味”“神了”；含具体人名、群名、@ 或拍一拍模板的旧条目继续过滤。
- 对已有证据达到至少两次、且含义高度明确的 8 个 AI 黑话条目，已补写最小化语义和场景（不新增证据、不覆盖人工条目），让它们立即可参与检索和复核。
- 回复提示在玩梗、荒诞前提和调侃场景下主动优先匹配一个学习到的句式/黑话，允许短的误解、身份反转或情绪升级。

## 是否会持续变得更明确

会。当前机制是“出现证据 → 条目计数 → 达到复核阈值 → 用新上下文更新含义”，而不是一次推断永久定论。新规则尤其保证了含义为空时不会停止复核。模型重启后会加载本轮提示和阈值修改；旧数据库条目不会被删除，会在后续出现时逐步补足含义。

## 运行限制

当前 QQ 群真实连续样本仍然很短，很多条目只有 1–5 次出现；因此“高频”在这个群里需要更多实际聊天轮次才能稳定。现有自主生活分享为 0，表达学习还受到 learner 模型 45 秒硬超时/连接错误影响；API 失败时条目会保留证据而等待下一轮，不会伪造含义。`config/model_config.toml` 已把 learner 任务收敛到 Mistral 小模型并延长到 90 秒，减少在多个不可用候选之间耗时失败。

本轮只改学习策略、候选恢复和提示词，没有批量编造或删除群聊记忆。主 bot 未重启，需手动重启后生效。
