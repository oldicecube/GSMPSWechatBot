# 持久化定时提醒

迁移旧 Agent Tool `manage_scheduled_reminder`，供原生 MaiBot Planner 使用。无需外部 Python 包，也不启动旧 LLM 服务或旧自主循环。

支持为当前群的当前请求者创建单次提醒、查询活动提醒和取消待处理提醒。到期后唤醒当前群的 MaiBot，由核心按人设决定回复；不绕过微信转译发送。用户可以直接说“十分钟后提醒我检查备份”“看看我的提醒”“取消刚才那条提醒”。时间不明确时应先询问。

首次加载会生成默认配置：启用插件、时区 `Asia/Shanghai`、每 5 秒巡检。每人每群最多 20 条活动提醒，时间范围为未来 10 秒至 366 天，不支持周期任务。数据保存在插件独立数据目录的 `reminders.sqlite3`，重启后继续处理。

工具参数只有 `action / title / remind_at / event_id`。请求者、群和消息身份通过 Host 保留字段 `_request_context` 注入，并使用 `message.get_by_id` 校验真实消息；不会信任模型自行提供的身份。依赖本仓库 Host 的请求上下文补丁，不能把插件单独复制到未提供该字段的旧 Host 后宣称可用。

`submitted` 只表示 Host 已接受任务，不等于微信已送达。Host 明确拒绝时最多尝试 5 次；RPC 超时、结果不明或提交过程中进程中断时标记 `uncertain`，不自动重复提交。查询活动提醒可看到此状态及原因。

与 `mai-life` 不同：本插件管理用户自己的提醒；`mai-life` 管理 Bot 生活日程与主动话题。它们使用不同工具名和数据库，不读取、改写或重复派发对方任务。不要为同一用户请求同时调用两个工具。

旧 `data/bot.sqlite3` 中的历史记录不自动重放。本次迁移检查发现只有 1 条 `completed`，没有 `pending / dispatching` 记录。
