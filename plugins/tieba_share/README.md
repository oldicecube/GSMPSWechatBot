让麦麦从贴吧搬运帖子：选好要逛的吧，定时或手动搬运一轮，把整帖渲染成一张长图发送，或打包成一条聊天记录。

---

## 注意事项

- **吧的配置**：在「内置吧（可多选）」中勾选常用吧（默认仅勾选「搬石」），未列出的吧写入「自己加的吧」，每行一个；吧名末尾的「吧」字可省略。
- ⚠️ **反爬拦截**：出现 403 或安全验证时，本轮中止并冷却 15 分钟，不会被当作「无新帖」；调大「抓取 → 请求间隔」可降低触发概率。
- **去重机制**：已搬运的帖子不会重复搬运；记录保存在 `data/plugins/mizuku003.tieba-share/moved.json`（默认每吧 500 条），需要重新搬运时使用 `/搬石 重置 [吧名]`。
- **发送内容**：每帖都会渲染成长图（过长会切成多张），不提供关闭长图的选项：关闭后没有可发送的内容。「发送」一节只决定是否打包成聊天记录、是否附带视频。长图渲染失败时该帖不发送，留待下一轮重试，不会退回为纯文字。
- **长图样式**：「贴吧原页面」按手机版页面截图（顶栏、页脚、推广按钮已清除）；「自绘卡片」由插件排版，宽度更小、更省流量。两种样式都会把正文里的插图补进长图，数量受「长图里最多几张图」限制。
- **长图渲染与 Playwright 版本**：1.1.7 起「贴吧原页面」默认用「零外链」方式渲染 —— 渲染前先把样式表和装饰图全部内嵌、并加一条禁止外链的 CSP，页面不再发出任何网络请求，因此主程序 Playwright 版本不再影响出图。这个方式可以在「发送 → 原页面渲染方式」里改回「原生」（让浏览器自己加载外链，出图与以前一致，但要求主程序 Playwright 在 1.61 以上）。原先的问题是主程序 1.60 及更早版本把网络拦截函数当成两个位置参数调用（`TypeError: got multiple values for argument 'allow_network'`），页面只要发出一个外链请求就永远等不到加载完成，最后超时、一张图都出不来——现在页面不发请求，这条路径根本走不到。代价是每帖多花 1~2 秒预下载这些资源（原页面本来也要下载它们，只是改成提前并发拉取）。用官方 `uv sync` 装的 1.3.x 主程序锁的是 Playwright 1.58，不升级也能正常出图；升级到 1.61 以上仍然推荐，主程序的其它渲染路径不受这条保护。
- **聊天记录**：开启「打包成聊天记录」后，本轮内容合并为一条聊天记录。长图以本地文件路径写入，转发帧内只有路径字符串，因此与图片体积无关；若有帖子未能进入本次记录，本轮不发送该帖，留待下一轮重试。
- ⚠️ **协议端要能读到长图**：路径只是字符串，图片由协议端自己去读盘。协议端与宿主装在同一台机器上时无需配置；**协议端跑在容器里**（如 snowluma 的 Docker 部署）时，要把 `data/plugins/mizuku003.tieba-share/pages` 按**相同绝对路径**只读挂进容器，否则长图发出去是空的。
- **楼中楼**：每层正文下会带上几条评论，楼主自己的回复优先。评论正文、帖子点赞数与翻页均通过贴吧 protobuf 接口获取；该接口不提供评论点赞数，因此评论无法按赞排序。
- **视频**：视频帖连同视频一起发送；超过「视频大小上限」的视频整条跳过，也不发送链接。
- ⚠️ **适配器支持**：视频经宿主的自定义消息段通道发送，NapCat / snowluma 支持，其他适配器可能无法接收（此时仅显示链接）。
- **会话范围**：仅向群聊发送；同一群每轮只投递一条。群名单默认为**白名单**且默认为空，即安装后不向任何群投递，需在「定时 → 群名单」中添加群号后方可生效。
- ⚠️ **代理**：插件不读取系统代理（`trust_env=False`），如需代理请在「抓取 → 代理」中填写。
- **自动搬运**：默认关闭。开启后按「隔多少分钟搬一次」或「每天定点」轮询（填写定点后忽略间隔）；启动后不会立即搬运，需等到下一个时间点。两种模式均按绝对时刻排期，重启或单轮耗时过长均不会跳过既定的时间点。
- **免打扰时段**：默认 23:00~08:00，区间内跳过定时搬运且不补发；`/搬石` 等手动指令与麦麦调用不受影响。
- **发送时刻略有提前**：填写「提前开始」后，插件提前取回帖子，到时间点再发送；间隔与定点两种模式均生效。
- **`/搬石` 与 `/搬视频`**：前者按配置搬运，后者只搬运视频帖；指令不再回复「开始搬运」一类的开场白，仅在出错时于群内说明。
- **结束语**：一轮搬运结束后，插件在同一个群里补一句结束语，内容在「发送」一节配置，留空则不发送；搬运成功时没有其他提示。
- **工具调用的发送参数**：由面板「工具」一节单独控制，与「发送」互不影响。
- **仅供个人学习与自用**：免登录读取贴吧公开页面，请遵守贴吧服务条款。
- **内容版权**：搬运内容的版权归原作者所有；插件仅做转发，不代表作者观点。
- **使用风险自负**：作者不对因使用本插件产生的任何后果负责（内容争议、IP 受限、群聊体验等）。

## 安装

1. 将插件目录放入宿主的 `plugins/` 目录。
2. 在 WebUI 插件页启用（安装后默认关闭）。
3. 在 WebUI 面板中修改配置；插件目录下的 `config.toml` 由宿主按默认值生成，无需手写。
4. 在「搬石」一节配置吧：勾选内置吧，未列出的吧填入「自己加的吧」。

搬运记录保存在宿主的 `data/plugins/mizuku003.tieba-share/` 目录。依赖 `httpx` 已在 `_manifest.json` 中声明，由宿主自动安装。

## 指令

| 指令 | 说明 |
|---|---|
| `/搬石` | 按配置搬运一轮，发送到当前群 |
| `/搬视频` | 本轮仅搬运视频帖，忽略「只搬哪种帖」的设置 |
| `/搬石 状态` | 查看每个吧的搬运条数与最后一次搬运时间（仅管理员） |
| `/搬石 重置 [吧名]` | 清空搬运记录；不填吧名则清空全部（仅管理员） |
| `/搬石 重置 冷却` | 手动解除反爬冷却（仅管理员） |
| `/搬石 帮助` | 输出用法说明 |

`/搬石` 与 `/搬视频` 需要权限：管理员，或「可搬石的群」里列出的群（整群可用）。`/搬石 状态`、`/搬石 重置`、`/搬石 重置 冷却` 属于维护命令，仅管理员可用。名单在插件配置的「权限」一节填写，直接填 QQ 号即可（`qq:123456` 的旧写法同样识别）；主程序终端始终可用。

> 两张名单均留空时，插件沿用宿主配置 `[plugin] permission` 中的账号。该名单由整个插件系统共用，修改会影响其他插件，因此建议使用插件自身的「权限」一节。

## 让麦麦自己搬

插件向麦麦提供 `tieba_share` 工具，在群内说「搬个石」即可触发，结果发送至当前会话。

- **发送参数**：定时搬运与 `/搬石` 使用「发送」一节，工具调用使用「工具」一节，两节互不影响。
- **吧的范围**：「限定吧」留空时麦麦可选择任意吧；填写后仅限于所列的吧。
- **可用参数**：吧名（不填则使用配置值）、条数（默认 1，最多 5）、帖子类型（默认跟随「工具」一节，也可临时指定）。
- 工具调用同样受去重、帖子类型筛选与「带原帖链接」影响，并与手动搬运共用同一把锁；上一轮尚未结束时调用会提示稍后再试。

## 数据来源

- 帖子列表与正文：贴吧移动站（`tieba.baidu.com/mo/q/m`），免登录，仅使用访客 cookie。
- 图片：只从贴吧自己的图库域名取（`imgsrc.baidu.com` 取原图，`tiebapic.baidu.com` 取带签名缩略图）；正文里出现的外链图床一律不请求。

## 依赖

- `httpx`（已在 `_manifest.json` 里声明，由宿主自动安装）；长图渲染用宿主自带的渲染能力，不需要额外依赖。

渲染走的是 SDK 的裸调用通道。包装层 `ctx.render.html2png` 不接受 RPC 超时参数，RPC 层固定按 30 秒算（`runner/rpc_client.py`），而贴吧原页面冷启动渲染常要 20 秒以上，所以插件直接调 `cap.call`（在 SDK 的 `_ALLOWED_RAW_HOST_METHODS` 里）把超时传下去，并用 `_normalize_capability_result` 归一化结果。这两项属于 SDK 内部接口，当前在 SDK 2.x 上验证可用；插件对它们做了能力探测，缺失时退回公开的 `ctx.render.html2png` —— 那条路 RPC 超时写死 30 秒，长页面可能渲不出来，但功能不会整体失效。

## 更新记录

**1.1.8**

- 修复：帖子带视频时，整条聊天记录会被协议端整条拒收，群里一条也收不到
  （主程序日志里是 `message element "video" must be the only segment in a message`）。
  起因是视频段被塞进了长图所在的同一个转发节点，部分协议端/网关（如 SnowLuma）
  要求视频必须独占一条消息，NapCat 则容忍混装 —— 于是同一个插件换个适配器就整轮发空。
  现在每个视频单独占一个转发节点，两种适配器都能发。
- 修复：一轮什么都没发出去时，日志会说「长图都没渲出来」，而实际往往是投递失败
  （长图明明都渲好了）。这句猜错的原因会把排查引到完全相反的方向，现在只说「没发出去」，
  并提示去主程序日志里看 `SendService` 那一行。

**1.1.7**

- 「贴吧原页面」渲染前把样式表和装饰图全部内嵌、并加一条禁止外链的 CSP，页面零网络请求。
  主程序搭配 Playwright 1.60 及更早版本时那个「每个外链请求都抛 `TypeError`、最后超时出不了图」
  的缺陷因此不再影响本插件，1.58 也能正常出图。
- 出图结果与「原生」方式基本一致（实测像素差异 0.01%~0.2%，集中在表情边距）。
- 新增配置项「原页面渲染方式」：`零外链`（默认）或 `原生`。
  想省掉那 0.8~1 秒预下载、并且确认主程序 Playwright 在 1.61 以上，可以切到 `原生`；
  切过去之后渲染失败会自动回落到自绘卡片，不会空发。
- 装饰图下载失败或超出预算（整页 2 MB、单图 512 KB）时该图留空，不影响文字与正文图。
- 修复上一条带来的副作用：贴吧用 `img[src*="tb/editor"]` 这类属性选择器控制表情大小，
  图片换成内嵌数据后选择器失配，楼层正文里的表情会按原图尺寸撑开。
  现在换图时把原地址留在 `data-orig-src` 上，并把样式里的 `[src…]` 一并改指过去，
  表情与其它依赖原地址的排版都恢复原样。
- 长图不再降档重渲，倍率固定 1.5。降档是「再渲一遍」，总时间只会更长 ——
  实测 1.5 换 1.0 只省 0.15 秒，而一整轮里光是下载样式表和装饰图就要 0.8~1 秒，
  真正慢的是网络。现在长图渲完会像视频那样在日志里打出实际体积，方便核对。
  唯一保留的门槛是主程序单次回传 12 MB 的硬顶，正常层数碰不到。
